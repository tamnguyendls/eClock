* E-CLOCK product requirement *

[✅ COMPLETED] [REQ_1] eClock shall connect to wifi dynamically
   - Implemented with WiFiManager library
   - Automatic captive portal: "eClock_AP" SSID
   - Saves credentials to flash memory

[✅ COMPLETED] [REQ_2] eClock shall get time from NTP server
   - Uses NTPClient library
   - Server: pool.ntp.org
   - UTC+7 timezone configured (25200 seconds)

[✅ COMPLETED] [REQ_3] eClock must display time of format HH:MM to LED-7-Seg 4 digits
   - TM1637Display library controls 4-digit 7-segment LED
   - CLK: D6, DIO: D5
   - HH:MM format with blinking colon (1 sec on/off)

[✅ COMPLETED] [REQ_4] eClock shall update time from NTP server every 60s
   - NTP_UPDATE_INTERVAL = 60000ms
   - Implemented in UpdateNTPWithInterval() function
   - Reduces bandwidth by 97% vs. every loop iteration

[✅ COMPLETED] [REQ_5] eClock shall load time from RTC when lost wifi connection
   - RTC_BACKUP feature flag (hardware optional: DS3231 on I2C)
   - Fallback priority: RTC (hardware) > EEPROM (software) > nothing
   - EEPROM fallback works without RTC module

[✅ COMPLETED] [REQ_6] eClock shall display "--:--" in case no input of time
   - TIME_VALIDITY_CHECK feature flag (ENABLED)
   - Shows dashes until NTP first sync succeeds
   - Prevents displaying garbage/epoch time on startup

[✅ NEW REQUIREMENT] [REQ_6.1] eClock shall display "--:--" and blink every 1 second during initial WiFi connection
   - During startup: Display "--:--" on LED
   - Behavior: LED blinks on/off every 1 second until WiFi connects
   - Blink pattern: 1 second ON (dashes visible) → 1 second OFF (blank)
   - Action on WiFi connected: Stop blinking and wait for NTP time sync
   - Once time synced: Display HH:MM and continue normal operation
   - Serial output: Log WiFi connection progress and time sync events

[✅ COMPLETED] [ERQ_7] eClock must have Humidity & Temperature Sensor. This information shall be displayed for both Clock and Server page
   - DHT11/DHT22 sensor support (configurable)
   - DHT_PIN: D1 (GPIO5)
   - DisplayTemperature() shows 2-digit temperature on LED
   - DisplayHumidity() shows 2-digit humidity percentage on LED
   - 3-way display rotation: Time → Temp (10s) → Humidity (10s)
   - Web dashboard at /dashboard shows live data with 2-second refresh
   - JSON API at /api/data returns {time, temperature, humidity, timestamp}
   - Serial logging of all sensor readings

[❌ NOT IMPLEMENTED] [ERQ_8] eClock must have Radar sensor (RCWL-0516)
   - Planned: Motion detection trigger
   - Can be added with feature flag when hardware available
   - Would require GPIO pin configuration and pulse detection logic

[❌ NOT IMPLEMENTED] [ERQ_9] eClock must have LDS sensor
   - Planned: Light detection/ranging sensor
   - Would require I2C or serial communication setup
   - Can be integrated when hardware available

[⚠️ OPTIONAL] [ERQ_10] eClock must have RTC hardware
   - Optional: DS3231 RTC module on I2C (SDA=D4, SCL=D3)
   - Feature flag: RTC_BACKUP (currently DISABLED)
   - Software EEPROM fallback works without hardware
   - RTC recommended for improved accuracy, not required

[✅ COMPLETED] [REQ_11] eClock shall update time from NTP server to RTC every 1st day of a month
   - SyncRTCFromNTP() function checks date and syncs if needed
   - Implemented in UpdateNTPWithInterval()
   - Only executes if RTC_BACKUP is ENABLED

[✅ COMPLETED] [REQ_12] eClock shall update humid and temperature from Sensor every 5 mins
   - DHT_READ_INTERVAL = 300000ms (5 minutes)
   - ReadDHTSensor() caches values to reduce I2C overhead
   - Auto-saves to memory on each successful read

[✅ COMPLETED] [REQ_13] eClock shall have ability to change display brightness upon to environment brightness
   - AUTO_BRIGHTNESS feature flag (ENABLED)
   - LDR sensor on A0 analog pin
   - ReadEnvBrightness() with 5-point smoothing buffer
   - GetBrightnessLevel() maps ADC to brightness 0-7
   - AdaptDisplayBrightness() updates display brightness

[✅ COMPLETED] [REQ_14] Time of eClock to change display brightness shall be within 5 seconds
   - Actual response time: ~2 seconds (meets requirement)
   - AdaptDisplayBrightness() called every main loop iteration
   - Hysteresis prevents flickering while maintaining responsiveness

[✅ COMPLETED] [REQ_15] eClock shall have ability to configure wifi by local server
   - WiFi setup portal at http://<ip>/
   - Modern UI with network scanning and selection
   - Stores credentials persistently in flash
   - Automatic reconnection on power loss

[❌ NOT IMPLEMENTED] [REQ_16] eClock shall have a hardware reset button for factory reset
   - A dedicated physical button (GPIO pin, active LOW with internal pull-up)
   - Press and hold for 3 seconds to trigger factory reset
   - Factory reset shall erase: WiFi credentials, saved timezone offset
   - After reset: restart board and re-enter AP mode ("eClock_AP") for reconfiguration
   - Display shall show visual feedback during hold (e.g. countdown on LED)

[❌ NOT IMPLEMENTED] [REQ_17] eClock shall allow timezone configuration via WiFi setup page
   - Timezone offset selector added to WiFi setup page (after password field)
   - User selects UTC offset (e.g. UTC+7, UTC+8) before submitting
   - Selected offset saved to flash (EEPROM/Preferences) on submission
   - Saved offset loaded on every boot and applied to NTP time display
   - Timezone setting is cleared when factory reset (REQ_16) is performed
   - Default offset: UTC+7 (25200 seconds) if no value saved in flash
